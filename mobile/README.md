# mobile — Flutter (기사 앱)

기사가 쓰는 화면 전부. **관리자 검수 화면은 여기가 아니라 `admin-web/`이다.**

API 계약은 `docs/MOVE_AI_05B_API계약.md`.
화면 설계 원칙은 `docs/MOVE_AI_기획디자인_이해자료.pdf` 3부.

**디자인 시안** — [Figma](https://www.figma.com/design/4girj3oH3g2JxyIM5erfUC/Untitled?node-id=0-1)
시안과 아래 원칙이 어긋나면 **시안을 따르고**, 카드 종류·정보 우선순위만 지킨다.

## 스택

```
Flutter 3.24+ / Dart 3.5+
상태관리   최소한으로. Provider 또는 setState 로 충분하다
HTTP      http 또는 dio
녹음      record (마이크 권한 처리 필요)
```

**상태관리 라이브러리에 시간을 쓰지 않는다.** 화면 4개짜리 앱이다.

## 화면

```
S1  배송 목록      GET /api/delivery-jobs
S2  배송 상세      GET /api/delivery-jobs/{id} → [현장 도착] → 차량 확인
S3  Last 100m 안내 POST /api/guidance → next → complete   ★ 시연의 중심
S4  현장 팁 등록   POST /api/reports → PATCH transcript → POST extract
```

`S3`가 이 앱의 전부다. 나머지는 거기 도달하기 위한 화면이다.

## 설계 규칙

**채팅처럼 보이면 안 된다.** 기사는 운전 중이거나 카트를 밀고 있다.
현장 지식은 말풍선이 아니라 **짧은 신호 카드**다.

카드는 세 종류뿐이다. 서버가 `kind`로 내려준다.

```
WARNING    주의   위험·제약은 있으나 해법은 확인되지 않음
ACTION     행동   무엇을 하면 되는지 원문에 명확히 있음
REFERENCE  참고   알아두면 좋지만 당장 행동은 아님 (기본 접힘)
```

**주의 카드에 행동 문구를 붙이지 않는다.** 기사가 대안을 말하지 않았으면
시스템도 말하지 않는다는 원칙이 화면에서 지켜져야 한다.

정보 우선순위:

```
1. 현재 위치 / 단계     2. 다음 이동 행동     3. 주의
4. 추가 팁              5. 다음 버튼
```

지도는 보조다. 차별점은 카드다.

## 반드시 구현할 것

- **`isRecentlyAdded=true` 카드에 "새로 추가된 팁" 배지.**
  시연에서 "방금 그 제보가 여기 나왔다"를 짚는 유일한 장치다. 이게 없으면 2막이 약해진다.
- 마지막 단계 도착으로 자동 완료하지 않는다. **[배송 완료] 버튼이 유일한 트리거.**
- `conditionLabel`이 있으면 카드에 조건 라벨로 표시한다 ("비 오는 날", "큰 박스인 경우").

## 인증

구현하지 않는다. 기사 계정 하나로 고정한다.

## 시연 방식 — 미리 정해야 한다

녹화 방법이 개발 방식을 바꾼다.

| 방식 | 장점 | 주의 |
|---|---|---|
| **Android 에뮬레이터** | 화면 녹화가 쉽다. 권장 | 마이크가 호스트 마이크로 잡히는지 확인 |
| 실기기 + 미러링 | 실제 앱처럼 보임 | 미러링 도구·케이블 필요. 녹화 화질 |
| Flutter Web 빌드 | 브라우저에서 바로 녹화 | 마이크 권한·CORS 추가 확인 필요 |

**에뮬레이터를 권한다.** 녹음(`S4`)이 에뮬레이터에서 되는지는 본선 전에 확인한다.
안 되면 `S4`만 실기기로 찍거나, 텍스트 입력으로 대체한다.
