# frontend — React + TypeScript

API 계약은 `docs/MOVE_AI_05_구현_상세명세.md §4`.
화면 설계 지침은 `docs/MOVE_AI_기획디자인_이해자료.pdf` 3부.

## 화면

```
기사 — 배송 목록 → 배송 상세 → [현장 도착] → 차량 확인
기사 — Last 100m 안내   단계 / 다음 이동 / 카드 / [다음] / [배송 완료]
기사 — 현장 팁 등록     장소·위치 선택 → 녹음 → STT 확인·수정 → 제출
관리자 — 검수          음성 · 원문 · AI 결과 · 근거 구절 → 승인 / 수정 승인 / 반려
```

## 설계 규칙

**채팅처럼 보이면 안 된다.** 기사는 운전 중이거나 카트를 밀고 있다.
현장 지식은 말풍선이 아니라 **짧은 신호 카드**다.

카드는 세 종류뿐이다.

```
WARNING    주의   위험·제약은 있으나 해법은 확인되지 않음
ACTION     행동   무엇을 하면 되는지 원문에 명확히 있음
REFERENCE  참고   알아두면 좋지만 당장 행동은 아님 (기본 접힘)
```

**주의 카드에 행동 문구를 붙이지 않는다.** 기사가 대안을 말하지 않았으면
시스템도 말하지 않는다는 원칙이 화면에서 지켜져야 한다.

정보 우선순위:

```
1. 현재 위치 / 단계     2. 다음 이동 행동     3. 주의
4. 추가 팁              5. 다음 버튼
```

지도는 보조다. 차별점은 카드다.

## 반드시 구현할 것

- `isRecentlyAdded=true` 인 카드에 **"새로 추가된 팁" 배지**.
  시연에서 "방금 그 제보가 여기 나왔다"를 짚는 유일한 장치다.
- 검수 화면은 원문과 AI 결과를 **나란히** 배치한다.
  AI 결과를 JSON 그대로 노출하지 말고 카드로 보여준다.
- 마지막 단계 도착으로 자동 완료하지 않는다. **[배송 완료] 버튼이 유일한 트리거.**

## 인증

구현하지 않는다. 기사/관리자 전환은 화면 토글로 충분하다.
로그인 화면에 시간을 쓰지 않는다.
