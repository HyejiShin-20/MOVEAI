# admin-web — 관리자 검수 화면 (웹)

관리자가 AI 추출 결과를 원문과 대조해 승인·반려하는 화면. **이 앱은 화면 2개면 끝난다.**

API 계약은 `docs/MOVE_AI_05B_API계약.md §4-6`.

**디자인 시안** — [Figma](https://www.figma.com/design/4girj3oH3g2JxyIM5erfUC/Untitled?node-id=0-1)

## 스택

```
React 18 + TypeScript + Vite
라우팅   react-router (화면 2개라 없어도 됨)
HTTP    fetch 로 충분
```

**UI 라이브러리에 시간을 쓰지 않는다.** 좌우 분할 레이아웃 하나가 전부다.
`mobile/`과 같은 React 도구 체인을 사용하되 별도 앱으로 유지한다.

## 화면

```
W1  검수 대기 목록   GET /api/moderation/drafts?status=PENDING
W2  검수 상세        GET /api/moderation/drafts/{id}
                    → POST .../approve  또는  .../reject
```

## W2가 이 앱의 전부다

**원문과 AI 결과를 나란히 놓는다.** 좌우 분할이다.

```
┌─────────────────────────┬─────────────────────────┐
│ 기사가 말한 것            │ AI가 정리한 것            │
│                         │                         │
│ [음성 재생]              │  ┌───────────────────┐  │
│                         │  │ 위치  하역장 방화문  │  │
│ 받아쓴 원문              │  │ 내용  …            │  │
│ "아 방화문 옆에 요즘…"    │  │ 행동  …            │  │
│                         │  │ 근거  "…" ← 하이라이트│  │
│ (기사가 수정한 텍스트)    │  └───────────────────┘  │
│                         │  [승인] [수정 승인] [반려] │
└─────────────────────────┴─────────────────────────┘
```

**`source_excerpt`(근거 구절)를 왼쪽 원문에서 하이라이트하면 가장 좋다.**
"AI가 어디를 보고 판단했는지"가 한눈에 보이는 것이 이 화면의 존재 이유다.
시간이 없으면 오른쪽 카드에 텍스트로만 표시해도 된다.

**AI 결과를 JSON 그대로 노출하지 않는다.** 카드로 보여준다.
"AI를 믿는다"가 아니라 **"AI가 정리하고 사람이 확인한다"**는 인상이 화면 구조에서 나와야 한다.

## 주의

- 승인은 **동기 처리**다. 임베딩 생성까지 끝나야 응답이 온다.
  **스피너를 반드시 띄운다.** 실패하면 명시적 오류를 보여주고 재시도 버튼을 준다.
  조용히 넘어가면 검색되지 않는 지식이 생긴다.
  단, 서버는 `/embed` 외부 호출 중 DB 트랜잭션을 열지 않는다(`05B §4-6`).
- `target_type = UNKNOWN`인 초안은 **위치가 "확인 필요"로 표시**된다.
  관리자가 이걸 보고 판단할 수 있어야 한다. 숨기지 않는다.
- CORS 설정이 필요하다. 백엔드에서 `admin-web` 오리진을 허용한다.

## 인증

구현하지 않는다. 관리자 계정 하나로 고정한다.
